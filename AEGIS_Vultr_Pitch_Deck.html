THE PROBLEM // Enterprise Adoption Bottleneck
INDUSTRY PAIN POINTS

Why Autonomous AI Agents Have Failed in Enterprise Production

LLM agents have powerful reasoning capabilities, but lack safe, sandboxed execution primitives.

1. Unbounded Host Risk

Prompt Injections & Destructive Code
  • Traditional agents execute scripts directly on host runtimes or developer laptops.
  • Malicious or malformed inputs can perform destructive filesystem commands (rm -rf).
  • No resource capping results in CPU exhaustion and thread-pool starvation.
The Consequence: Enterprise CISOs block agent deployment to protect infrastructure.

2. Cloud Metadata & SSRF Leaks

Credential Exfiltration Vectors
  • Agents equipped with web scraping tools can be coerced into requesting internal cloud endpoints.
  • Attackers target 169.254.169.254 to steal IAM tokens and Vultr API credentials.
  • Host environment variables (API keys, DB secrets) leak into subprocess environments.
The Consequence: Cloud accounts breached through automated agent web traversal.

3. Hallucination vs. Real Work

Absence of Verifiable Proof
  • Standard conversational agents generate plausible-sounding text instead of executing real calculations.
  • A financial controller cannot accept hallucinated ledger reconciliation numbers.
  • No audit trail exists linking agent assertions to signed execution outputs.
The Consequence: "Agent demos" remain toys; enterprises cannot trust them with real money.
Root Cause: Absence of Containment-First Architecture and Cryptographic Receipts

THE AEGIS SOLUTION // Containment-First Architecture
SYSTEM ARCHITECTURE

Dual-Layer Defense: Centralized Orchestration + Ephemeral Sandboxes

Separating the reasoning brain from the execution muscle to guarantee mathematical containment.

Layer 1: Centralized Control Plane (Port 4000)

TypeScript / Node.js Engine on Vultr VM
  • Policy Gate Engine: Pre-evaluates every agent tool call against strict security rules (SSRF block, path confinement, airgap).
  • Zero-Secret Process Sanitization: Strips all host API keys, SSH credentials, and environment variables before sandbox dispatch.
  • Cryptographic Receipt Signer: Issues Ed25519 digital signatures and hashes every stdout, stderr, and artifact into a Merkle sequence.
  • Human-in-the-Loop Inbox: Suspends high-risk external actions (payment execution, cold outreach) until a human approves.
Orchestrator Boundary

Layer 2: Hardened Vultr Sandbox Worker (Port 4100)

Docker Daemon & Ephemeral Containers on Vultr VM
  • Unprivileged Container Isolation: Runs under non-root user 1000:1000 with read-only rootfs and an isolated /workspace.
  • Headless Chromium Browser: Drives live DOM extraction and screenshots without network egress to cloud metadata (169.254.169.254).
  • Python 3.12 Analytics Engine: Standard library analytics runtime for statistical scoring, 3-way match, and MCDA optimization.
  • Supervisor Watchdog: Forcibly reaps any runaway process tree or infinite busy loop at 1,400ms (exit code 124).
Zero-Trust Sandbox
Secure RPC: Control Plane dispatches commands over HMAC-SHA256 authenticated channels

MCDA Mathematical Formula

Multi-Objective Normalization in Sandbox

Each bid is evaluated using a normalized utility function:
Score = w₁·(B_target / P_quote) + w₂·(SLA / 100) + w₃·(D_max / D_quote) + w₄·(R_vendor / 10)

  • Prevents selecting cheapest bid if delivery time or SLA violates enterprise standards.
  • Computes exact budget variance: Net Savings = Target Budget - Winning Bid.

AUDITABILITY // Cryptographic Execution Receipts
MERKLE PROOFS

Immutable Ed25519 Execution Receipts & Hash Chains

Every tool dispatched into the sandbox produces a cryptographically sealed, tamper-evident audit record.

Structure of an Execution Receipt

Complete Execution Attestation

Each receipt captures complete ground-truth telemetry from inside the container:

  • Identity: Unique receiptId, missionId, and sequential stepIndex.
  • Execution Payload: Language, executed script filename, policy rule ID.
  • Runtime Output Hashes: SHA-256 hash of stdout, stderr, and generated artifacts.
  • Timestamps & Telemetry: Started epoch, completed epoch, duration in milliseconds, exit code.
  • Chaining: Previous receipt hash (prevReceiptHash) linking to the previous step.
  • Digital Signature: Ed25519 signature generated with Control Plane's private key.

Why This Matters for Enterprises

Mathematical Non-Repudiation
  • Zero Trust Required: A third-party auditor can independently verify the signature chain without trusting the agent.
  • Tamper Evidence: Altering a single character of output or an artifact invalidates the SHA-256 hash and breaks the chain.
  • Compliance Ready: Satisfies SOC2, HIPAA, and ISO 27001 requirements for automated system audits.
  • Workspace Inspector: Frontend allows users to click any receipt and inspect the full cryptographic verification breakdown.
SOC2 / ISO 27001 Compliant Auditability
Ed25519 receipts can be exported as JSON or verified live via /api/missions/:id/verify
